---
name: slurp-instrument
description: Design and implement a minimal product event tracking plan using Slurp; validate identities, task outcomes and collection.
---
Read references/learning-loop.md. Inspect actual code and existing events. Produce product context, metric definitions, the smallest useful event mapping, instrumentation changes and tests. Verify collection through Slurp and distinguish accepted events from published archives. Include eligible attempts and failures, stable identity and attempt IDs. Use slurp status, describe, sync and sql --file as needed. Use what the app already has before adding an SDK: a Segment or Sentry SDK only needs its host or DSN changed (see "Instrument and connect" in the slurp skill). To capture what users say in a web app, mount the feedback widget; it sends `feedback` events. Give each sender (web, ios, a webhook) its own publishable key so `sender` tells them apart. Credentials stay in secret stores. Human approval precedes production releases.
